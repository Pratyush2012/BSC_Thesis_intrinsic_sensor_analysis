\chapter{Data Processing Pipeline}
\label{ch:processing}
This chapter describes the sequence of preprocessing stages that convert the raw per-sensor log files described in \Cref{ch:setup} into a window-level dataset suitable for feature extraction (\Cref{ch:feature}) and modelling (\Cref{ch:classification}). The pipeline is implemented as a sequence of self-contained Jupyter notebooks (\texttt{01\_qc.ipynb} through \texttt{05\_windowing.ipynb}) backed by the reusable Python modules in \texttt{src/}. \Cref{fig:pipeline_overview} shows the overall data flow.

\section{Quality Control}
\label{sec:qc_screening}

Quality control is implemented in \texttt{01\_qc.ipynb} and operates on each run independently before resampling, so that faulty runs can be excluded from the pipeline outright rather than propagating corrupted data downstream. For each sensor frame $X = \{(t_i, x_i)\}_{i=0}^{N-1}$ a compact diagnostic vector is computed:
\begin{itemize}
    \item Sample count $N$ and total duration $T = t_{N-1} - t_0$.
    \item Median sample period $\tilde{\Delta t} = \mathrm{median}(\Delta t_i)$ and median sample rate $\tilde{f}_s = 1/\tilde{\Delta t}$.
    \item 99th-percentile and maximum period $\Delta t_{p99}$, $\Delta t_{\max}$.
    \item Gap ratio $\Delta t_{\max} / \tilde{\Delta t}$.
    \item Number of large gaps $N_{\mathrm{gap}} = |\{i : \Delta t_i > 5\tilde{\Delta t}\}|$.
\end{itemize}
A run is accepted (\texttt{pass\_all = True}) if and only if all of the following hold for every sensor:
\begin{enumerate}
    \item \emph{No large gaps:} $N_{\mathrm{gap}} = 0$.
    \item \emph{Sufficient duration:} $T \ge 30\,\text{s}$.
    \item \emph{Rate in expected range:} $70 \le \tilde{f}_s \le 100\,\text{Hz}$ for the IMU, $80 \le \tilde{f}_s \le 130\,\text{Hz}$ for the odometry.
\end{enumerate}
In addition, the first $5\,\text{s}$ of each accelerometer and gyroscope channel is inspected for static-bias drift, and the per-axis minimum and maximum are checked against the configured full-scale range to flag saturation events. All nine production runs (four campus, five farm) passed every QC criterion. The per-run QC report (\texttt{reports/raw/\{run\}/qc\_report.\allowbreak json}) records the full diagnostic vector for reproducibility, and the companion \texttt{sanity.png} dashboard plots all six IMU channels and the odometry pair on a common time axis for visual inspection (\Cref{fig:sanity_dashboard}).

\section{Synchronisation and Resampling}
\label{sec:sync_resample}

The three intrinsic sensor streams (\Cref{ch:setup}) are produced by independent firmware loops on the on-board computer and the Teensy microcontroller, so each stream has its own start time, end time and sample-period jitter. Before any analysis can proceed, the three streams must be brought onto a common, uniformly spaced time grid. This is done in \texttt{02\_sync\_resample\_merge.ipynb}.

\paragraph{Target rate.}
The raw IMU samples at approximately $83\,\text{Hz}$ and the wheel odometry at approximately $83\,\text{Hz}$ on the farm logs (and $\sim 130\,\text{Hz}$ on the campus logs). Resampling to a single target rate has two purposes: it produces a uniform time grid that downstream code can treat as a regular discrete signal, and it harmonises the campus and farm data so that the same windowing and feature code applies without modification. A target rate of $f_s = 100\,\text{Hz}$ was chosen as a compromise between two constraints: it lies above the raw IMU rate (so that information loss from down-sampling is avoided) and it is high enough that frequency content up to the Nyquist limit of $\SI{50}{\hertz}$ is preserved, which covers the \SIrange{20}{40}{\hertz} wheel--surface interaction band identified in \Cref{sec:bg-features-ml}.

\paragraph{Resampling procedure.}
For each run, a unified time grid $\{t_k\}_{k=0}^{K-1}$ is generated from $t_{\min} = \min(t_0^{\mathrm{acc}}, t_0^{\mathrm{gyro}}, t_0^{\mathrm{odo}})$ to $t_{\max} = \max(t_N^{\mathrm{acc}}, t_N^{\mathrm{gyro}}, t_N^{\mathrm{odo}})$ in steps of $\Delta t = 1/f_s = 10\,\text{ms}$. Each sensor channel $x[\cdot]$ is then linearly interpolated onto this grid:
\begin{equation}
    x_{\mathrm{rs}}[k]
    \;=\;
    x[i] + \frac{t_k - t_i}{t_{i+1} - t_i}\,\bigl(x[i+1] - x[i]\bigr),
    \qquad
    t_i \le t_k < t_{i+1}.
    \label{eq:linear_interp}
\end{equation}
Linear interpolation was preferred over higher-order schemes (spline, sinc) because the raw sample period is short compared to the dominant signal timescales and the linear interpolant introduces only a small, flat low-pass response that does not distort the frequency bands of interest~\cite{Press2007}. The three resampled sensor frames are then merged on the common time column to produce a single per-run DataFrame with columns $(t_{\mathrm{rel}}, a_x, a_y, a_z, g_x, g_y,\allowbreak g_z, v_1, v_2)$.

\section{Cleaning}
\label{sec:cleaning}

QC asks whether the \emph{sensor} produced clean data; cleaning asks whether the \emph{vehicle} was in a state where the recorded vibration is attributable to terrain. Two such states are excluded (\texttt{04\_cleaning.ipynb}).

\paragraph{Low-speed segments.}
The accelerometer signature of a terrain only manifests once the wheels are actually rolling. When the robot is stationary, all observed acceleration variance comes from electrical sensor noise and would be assigned (incorrectly) to whatever terrain label was active at that timestamp. The net forward speed of the robot is computed from the two wheel velocities,
\begin{equation}
    \bar{v}(t) \;=\; \frac{v_1(t) + v_2(t)}{2},
    \label{eq:net_speed}
\end{equation}
and samples with $\bar{v}(t) < v_{\min}$ are unlabelled. The threshold $v_{\min} = 0.4\,\text{m/s}$ was chosen empirically: it sits above the noise floor of the wheel encoders at rest and below the lowest cruising speed observed on the farm logs, so genuinely moving samples are retained.

\paragraph{Turning segments.}
A second source of motion that is unrelated to terrain is in-place or sharp turning, which excites the body-frame yaw rate but produces vibration patterns that depend on slewing dynamics rather than the surface. The yaw rate is estimated from the differential wheel speeds and the inter-wheel distance $W = 0.67\,\text{m}$ (a constant of the Ricbot chassis) as
\begin{equation}
    \dot{\psi}(t) \;=\; \frac{v_1(t) - v_2(t)}{W},
    \label{eq:yaw_rate}
\end{equation}
and samples with $|\dot{\psi}(t)| > \dot{\psi}_{\max}$ are unlabelled. The threshold $\dot{\psi}_{\max} = 0.2\,\text{rad/s}$ corresponds to a turning radius of approximately $\bar{v}/\dot{\psi}_{\max} \approx 2$--$3\,\text{m}$ at typical cruising speeds, which is large enough that gentle trajectory corrections are still retained while sharp pivots and on-spot rotations are removed.

The two masks are combined disjunctively ($M = M_{v} \lor M_{\dot{\psi}}$), unlabelled samples are dropped, and the resulting cleaned dataset is saved to \texttt{data/interim/cleaned/cleaned\_\allowbreak dataset.csv} with the derived columns \texttt{net\_speed} and \texttt{yaw\_rate} retained for use downstream.

\section{Signal Filtering}
\label{sec:filtering}

The cleaned IMU streams contain useful terrain-related vibration up to the Nyquist frequency, but they also carry sensor noise and a small amount of mechanical resonance from the chassis that contributes no discriminative information about the surface. A causal, segment-aware low-pass filter is therefore applied to all six IMU channels in \texttt{04b\_filterin\allowbreak g.ipynb} before windowing. Odometry channels are left unfiltered; the wheel-encoder output is already heavily quantised and benefits little from further smoothing.

\subsection{Candidate Filters}

Three filter families were considered:
\begin{itemize}
    \item \textbf{Butterworth low-pass}~\cite{Butterworth1930}. A maximally-flat magnitude response in the pass-band with a monotonic roll-off, applied in forward--backward (zero-phase) form via SciPy's \texttt{scipy.signal.\allowbreak filtfilt} to avoid phase distortion of impulsive terrain events~\cite{Gustafsson1996}. Cut-off frequencies of $5$ and $10\,\text{Hz}$ were tested at filter orders $\{2, 4\}$, together with a $20\,\text{Hz}$ cut-off at order $2$.
    \item \textbf{Savitzky--Golay}~\cite{Savitzky1964}. A polynomial smoother that fits a low-order polynomial to a sliding window and replaces the centre sample with the fitted value; window-lengths $\{11, 21, 51\}$ samples were tested at polynomial order $2$, together with a polynomial-order-$3$ variant at window-length $21$.
    \item \textbf{Moving average}. A flat-kernel low-pass with window-lengths $\{5, 11, 21\}$ samples, included as a simple baseline.
\end{itemize}
All filters are applied per continuous segment rather than per run, because a single run can contain non-trivial gaps introduced by the cleaning stage; ignoring those gaps would smear the filter across discontinuities and create boundary artefacts.

\subsection{Filter Selection Criteria}

Each candidate filter is scored on every IMU channel and every sufficiently-long segment using four metrics:
\begin{enumerate}
    \item Pearson correlation $\rho$ between raw and filtered signal, measuring how much of the original waveform is preserved.
    \item Smoothness improvement $\sigma_{\dot{x}}^{\mathrm{raw}} / \sigma_{\dot{x}}^{\mathrm{filt}}$, the ratio of first-difference standard deviations, measuring how much short-timescale roughness has been removed.
    \item High-frequency noise reduction, the ratio of mean power above $20\,\text{Hz}$ before and after filtering.
    \item RMS residual $\|x_{\mathrm{raw}} - x_{\mathrm{filt}}\|_2 / \sqrt{N}$, a coarse measure of total energy removed.
\end{enumerate}
A filter is kept as a candidate only if its run-averaged correlation exceeds $0.90$ (the filter does not distort the waveform) and its noise-reduction ratio exceeds $2.0$ (the filter removes a meaningful amount of high-frequency content). Among the surviving candidates, the chosen filter maximises the composite score
\begin{equation}
    S \;=\; \frac{\rho \cdot R_{\mathrm{noise}} \cdot R_{\mathrm{smooth}}}{\mathrm{RMS}_{\mathrm{res}} + 0.01},
    \label{eq:filter_score}
\end{equation}
which rewards waveform preservation together with high-frequency attenuation and penalises a large residual.

\subsection{Selected Filter and Effect on Signals}

A second-order Butterworth low-pass with cut-off $f_{\mathrm{c}} = 20\,\text{Hz}$ applied in zero-phase (\emph{filtfilt}) form achieved the highest composite score across the five farm runs, with run-averaged metrics $\rho = 0.91$, $R_{\mathrm{noise}} = 7.8$, $R_{\mathrm{smooth}} = 2.2$ and $\mathrm{RMS}_{\mathrm{res}} = 0.64$. This cut-off was selected over the more aggressive $5$ and $10\,\text{Hz}$ alternatives because terrain texture and high-frequency wheel-surface interaction up to $\sim 20\,\text{Hz}$ carry discriminative information about surface roughness (\Cref{sec:bg-features-ml}); a tighter cut-off removed too much of that signal and dropped the correlation metric below the $0.90$ threshold. The selected filter and its metric summary are persisted to \texttt{data/interim/filtered/filter\_metadata.json} alongside the filtered dataset for reproducibility.

\section{Segmentation and Windowing}
\label{sec:windowing}

The cleaning step removes contiguous blocks of samples (the robot slowing to a stop, turning at the end of a row, etc.), so the filtered dataset is not strictly contiguous in time. A two-stage segmentation-then-windowing procedure (\texttt{05\_windowing.ipynb}) reconciles this with the fixed-size windows required by the feature extractor (\Cref{ch:feature}).

\subsection{Continuous-Segment Detection}

Within each run, consecutive samples are grouped into continuous segments by scanning the time differences $\Delta t_i = t_i - t_{i-1}$ and starting a new segment whenever
\begin{equation}
    \Delta t_i \;>\; \Delta t_{\mathrm{gap}}, \qquad
    \Delta t_{\mathrm{gap}} = 25\,\text{ms} \;=\; 2.5\,\Delta t,
    \label{eq:gap_threshold}
\end{equation}
where $\Delta t = 10\,\text{ms}$ is the resampled sample period (\Cref{sec:sync_resample}). The factor $2.5$ is conservative: it accepts the small per-sample jitter present in the raw logs ($\le 1\,\text{ms}$ in 99\% of cases, \Cref{sec:qc_screening}) while reliably breaking on the multi-sample gaps left by the cleaning step. Each segment is recorded with its run identifier, start and end times, sample count, and the label distribution within it.

\subsection{Fixed-Length Sliding Windows}

Each segment is then sliced into fixed-length, overlapping analysis windows. The window length $W$ and step size $S$ are chosen as
\begin{align}
    W &= \SI{2.0}{\second} \;\;\equiv\;\; 200 \text{ samples},
        \label{eq:window_size} \\
    S &= W \,(1 - r) \;=\; \SI{1.0}{\second} \;\;\equiv\;\; 100 \text{ samples},
        \qquad r = 0.5,
        \label{eq:step_size}
\end{align}
where $r$ is the overlap ratio. The $\SI{2}{\second}$ window is long enough to capture multiple cycles of the dominant terrain-driven oscillation ($\sim$\SIrange{5}{20}{\hertz}, i.e.\ tens of cycles per window) while remaining short enough that a typical terrain segment contains many windows for averaging. The $50\%$ overlap doubles the number of training examples and ensures that a transition crossing the boundary between two windows appears in at least one of them, which is useful for the transition analysis in \Cref{ch:results}. Windows are constructed strictly within a segment: they never straddle a gap, so no window mixes pre- and post-cleaning samples. This choice follows the standard windowing recipe in the activity-recognition and terrain-classification literature~\cite{Brooks2005,Bao2004}.

\subsection{Window Label Assignment}

Each window inherits a single terrain label from the per-sample labels inside it (the labelling stage of \Cref{sec:terrain_classes_and_labels} runs before windowing). The window label is the \emph{majority} label of its constituent samples; in the rare event of a tie the lexicographically smaller label wins. Because the upstream cleaning step has already removed turning and stationary samples, and because the conservative label ranges in \texttt{labels\_config.json} explicitly exclude transition regions, the majority label is unambiguous (\(>\!90\%\) of samples within a window agree on the label) in essentially all windows of the production dataset.

\subsection{Output of the Pipeline}

The windowing notebook produces a window-metadata DataFrame with one row per window and the following columns: \texttt{window\_id}, \texttt{run\_id}, \texttt{segment\_id}, \texttt{label}, \texttt{t\_start}, \texttt{t\_end}, \texttt{n\_samples}. The metadata table is saved to \texttt{data/processed/Farm/windowed\_metadata.csv} (for the farm dataset) and a parallel file is produced for the campus dataset. Together with the filtered per-sample dataset, this is the input to the feature extractor described in \Cref{ch:feature}.
