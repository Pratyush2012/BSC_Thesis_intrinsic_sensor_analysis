\chapter{Data Processing Pipeline}
\label{ch:processing}
This chapter describes the sequence of preprocessing stages that convert the raw per-sensor log files described in \Cref{ch:setup} into a window-level dataset suitable for feature extraction (\Cref{ch:feature}) and modelling (\Cref{ch:classification}). The pipeline is implemented as a set of self-contained Jupyter notebooks (\texttt{01\_qc.ipynb} through \texttt{05\_windowing.ipynb}) backed by the reusable Python modules in \texttt{src/}. \Cref{fig:pipeline_overview} shows the overall data flow:

\section{Quality Control}
\label{sec:qc_screening}

Quality control is implemented in \texttt{01\_qc.ipynb} and operates on each run independently before resampling, so that faulty runs can be excluded outright. For each sensor frame $X = \{(t_i, x_i)\}_{i=0}^{N-1}$, a compact diagnostic vector is computed:
\begin{itemize}
    \item Sample count $N$ and total duration $T = t_{N-1} - t_0$.
    \item Median sample period $\tilde{\Delta t} = \mathrm{median}(\Delta t_i)$ and median sample rate $\tilde{f}_s = 1/\tilde{\Delta t}$.
    \item 99th-percentile and maximum period $\Delta t_{p99}$, $\Delta t_{\max}$.
    \item Gap ratio $\Delta t_{\max} / \tilde{\Delta t}$.
    \item Number of large gaps $N_{\mathrm{gap}} = |\{i : \Delta t_i > 5\tilde{\Delta t}\}|$.
\end{itemize}
A run is accepted (\texttt{pass\_all = True}) if all of the following hold for every sensor:
\begin{enumerate}
    \item \emph{No large gaps:} $N_{\mathrm{gap}} = 0$.
    \item \emph{Sufficient duration:} $T \ge 30\,\text{s}$.
    \item \emph{Rate in expected range:} $70 \le \tilde{f}_s \le 100\,\text{Hz}$ for the IMU, $80 \le \tilde{f}_s \le 130\,\text{Hz}$ for the odometry.
\end{enumerate}
In addition, the first $5\,\text{s}$ of each IMU channel is inspected for static-bias drift, and the per-axis minimum and maximum are checked against the full-scale range to flag saturation events. All nine production runs (four campus, five farm) passed every QC criterion. Each run's QC report stores the full diagnostic vector, and a companion sanity dashboard plots all signal channels on a common time axis for visual inspection (\Cref{fig:sanity_dashboard}).

\section{Synchronisation and Resampling}
\label{sec:sync_resample}

The three intrinsic sensor streams (\Cref{ch:setup}) come from independent firmware loops with their own start times, end times and sample-period jitter, and must be brought onto a common, uniformly spaced time grid before any downstream analysis; this is done in \texttt{02\_sync\_resample\_merge.ipynb}.

\paragraph{Target rate.}
The raw IMU samples at approximately $\SI{83}{\hertz}$, and the wheel odometry at approximately $\SI{83}{\hertz}$ on the farm logs and approximately $\SI{130}{\hertz}$ on the campus logs. A target rate of $f_s = \SI{100}{\hertz}$ was therefore chosen because it sits at or above the raw IMU rate (avoiding down-sampling losses), and its Nyquist limit of $\SI{50}{\hertz}$ lies above the \SIrange{20}{40}{\hertz} wheel--surface interaction band identified in \Cref{sec:bg-features-ml}, so that band is preserved without aliasing. The common grid also harmonises the two campaigns so that the same windowing and feature code apply without modification.

\paragraph{Resampling procedure.}
For each run, a unified time grid $\{t_k\}_{k=0}^{K-1}$ is generated from $t_{\min} = \min(t_0^{\mathrm{acc}}, t_0^{\mathrm{gyro}}, t_0^{\mathrm{odo}})$ to $t_{\max} = \max(t_N^{\mathrm{acc}}, t_N^{\mathrm{gyro}}, t_N^{\mathrm{odo}})$ in steps of $\Delta t = 1/f_s = \SI{10}{\milli\second}$. Each sensor channel $x[\cdot]$ is then linearly interpolated onto this grid:
\begin{equation}
    x_{\mathrm{rs}}[k]
    \;=\;
    x[i] + \frac{t_k - t_i}{t_{i+1} - t_i}\,\bigl(x[i+1] - x[i]\bigr),
    \qquad
    t_i \le t_k < t_{i+1}.
    \label{eq:linear_interp}
\end{equation}
Linear interpolation was preferred over higher-order schemes (spline, sinc) because the raw sample period is short compared to the dominant signal timescales, and the linear interpolant introduces only a small, flat low-pass response that does not distort the frequency bands of interest~\cite{Press2007}. The three resampled sensor frames are then merged on the common time column to produce a single per-run DataFrame with columns $(t_{\mathrm{rel}}, a_x, a_y, a_z,\allowbreak g_x, g_y, g_z, v_1, v_2)$.

\vspace{-8mm}
\section{Labelling}
\label{sec:labelling_pipeline}

Terrain labels are applied to the resampled streams in \texttt{03\_labelling.ipynb} by loading the per-run \texttt{labels\_config.json} produced as described in \Cref{sec:terrain_classes_and_labels} and assigning each sample whose timestamp falls within a declared $[t_{\text{start}}, t_{\text{end}}]$ range its class label; samples outside any range are left unlabelled and are removed by the cleaning step (\Cref{sec:cleaning}). The label ranges themselves were obtained manually after each session from a hand-held video review (\Cref{sec:terrain_classes_and_labels}). For most runs the video clock was aligned to the sensor logs via identifiable events (run start, deliberate stops at terrain boundaries) using GNSS or Wi-Fi timestamps embedded in the video metadata; where neither was available, the alignment was instead recovered by cross-checking the video against the resampled-stream QC plots (\Cref{fig:sanity_dashboard}), where visible high-amplitude events (a cobblestone entry, a curb crossing) act as robust anchor points without external timing infrastructure.

\section{Cleaning}
\label{sec:cleaning}

QC asks whether the \emph{sensor} produced clean data; cleaning asks whether the \emph{vehicle} was in a state where the recorded vibration is attributable to terrain. Two such states are excluded (\texttt{04\_cleaning.ipynb}).

\paragraph{Low-speed segments.}
When the robot is stationary, all observed acceleration variance is due to sensor noise rather than terrain interaction and would otherwise corrupt the terrain class active at that timestamp. The net forward speed is computed from the two wheel velocities,
\begin{equation}
    \bar{v}(t) \;=\; \frac{v_1(t) + v_2(t)}{2},
    \label{eq:net_speed}
\end{equation}
and samples with $\bar{v}(t) < v_{\min}$ are unlabelled. The threshold $v_{\min} = \SI{0.4}{\meter\per\second}$ was chosen empirically to sit above the encoder noise floor at rest and below the lowest cruising speed observed on the farm logs.

\paragraph{Turning segments.}
Sharp turning is a second source of motion unrelated to terrain: it excites the body-frame yaw rate with patterns set by slewing dynamics rather than the surface. The yaw rate is estimated from the differential wheel speeds and the Ricbot inter-wheel distance
$W = \SI{0.67}{\meter}$ as
\begin{equation}
    \dot{\psi}(t) \;=\; \frac{v_1(t) - v_2(t)}{W},
    \label{eq:yaw_rate}
\end{equation}
and samples with $|\dot{\psi}(t)| > \dot{\psi}_{\max}$ are unlabelled. The threshold $\dot{\psi}_{\max} = \SI{0.2}{\radian\per\second}$ corresponds to a turning radius of $\bar{v}/\dot{\psi}_{\max} \approx \SIrange{2}{3}{\meter}$ at typical cruising speeds, which retains gentle trajectory corrections while removing sharp pivots and on-spot rotations.

The two masks are combined disjunctively ($M = M_{v} \lor M_{\dot{\psi}}$) and the unlabelled samples are dropped; the cleaned dataset retains the derived columns \texttt{net\_speed} and \texttt{yaw\_rate} for downstream use (\Cref{fig:cleaning_demo}).

\section{Signal Filtering}
\label{sec:filtering}

The cleaned IMU streams contain useful terrain-related vibration up to the Nyquist frequency, but they also carry sensor noise and a small amount of mechanical chassis resonance that contributes no distinct information about the surface. A zero-phase, segment-aware low-pass filter is therefore applied to all six IMU channels in \texttt{04b\_filtering.ipynb} before windowing. Odometry channels are left unfiltered: they enter the feature pipeline only as derived speed summaries of the IMU signals (\Cref{ch:feature}), not as raw signals.

\subsection{Candidate Filters}

Three filter families were considered:
\begin{itemize}
    \item \textbf{Butterworth low-pass}~\cite{Butterworth1930}: maximally-flat magnitude response in the pass-band with monotonic roll-off, applied in forward--backward (zero-phase) form via SciPy's \texttt{filtfilt} to avoid phase distortion of impulsive terrain events~\cite{Gustafsson1996}. Cut-off frequencies of $\SI{5}{\hertz}$ and $\SI{10}{\hertz}$ were tested at filter orders $\{2, 4\}$, together with a $\SI{20}{\hertz}$ cut-off at order $2$.
    \item \textbf{Savitzky--Golay}~\cite{Savitzky1964}: a polynomial smoother that fits a low-order polynomial to a sliding window and replaces the centre sample with the fitted value. Window-lengths $\{11, 21, 51\}$ samples were tested at polynomial order $2$, together with an order-$3$ variant at window-length $21$.
    \item \textbf{Moving average}: a flat-kernel low-pass with window-lengths $\{5, 11, 21\}$ samples, included as a simple baseline.
\end{itemize}
All filters are applied per continuous segment: a single run can contain gaps left by the cleaning stage, and ignoring those would smear the filter across discontinuities and create boundary artefacts.

\subsection{Filter Selection Criteria}

Each candidate is scored on every IMU channel and every sufficiently long segment using four metrics:
\begin{enumerate}
    \item Pearson correlation $\rho$ between raw and filtered signal, measuring how much of the original waveform is preserved.
    \item Smoothness improvement $R_{\mathrm{smooth}} = \sigma_{\dot{x}}^{\mathrm{raw}} / \sigma_{\dot{x}}^{\mathrm{filt}}$, the ratio of first-difference standard deviations, measuring how much short-timescale roughness has been removed.
    \item High-frequency noise reduction $R_{\mathrm{noise}}$, the ratio of mean power above $\SI{20}{\hertz}$ before and after filtering.
    \item RMS residual $\mathrm{RMS}_{\mathrm{res}} = \|x_{\mathrm{raw}} - x_{\mathrm{filt}}\|_2 / \sqrt{N}$, rough measure of total energy removed.
\end{enumerate}
A filter is retained as a candidate only if its run-averaged correlation exceeds $0.90$ (no waveform distortion) and its noise-reduction ratio exceeds $2.0$ (meaningful high-frequency attenuation). Among the surviving candidates, the chosen filter maximises the composite score
\begin{equation}
    S \;=\; \frac{\rho \cdot R_{\mathrm{noise}} \cdot R_{\mathrm{smooth}}}{\mathrm{RMS}_{\mathrm{res}} + 0.01},
    \label{eq:filter_score}
\end{equation}
which rewards waveform preservation and high-frequency attenuation while penalising a large residual.

\subsection{Selected Filter and Effect on Signals}

A second-order Butterworth low-pass with cut-off $f_{\mathrm{c}} = \SI{20}{\hertz}$ applied in zero-phase (\emph{filtfilt}) form was the only candidate to clear both gating thresholds across the five farm runs, with run-averaged metrics $\rho = 0.91$, $R_{\mathrm{noise}} = 7.8$, $R_{\mathrm{smooth}} = 2.2$ and $\mathrm{RMS}_{\mathrm{res}} = 0.64$ (\Cref{tab:filter_ranking}); it is also the top-ranked filter on the campus development data, so a single filter is used across both campaigns. The lower-cut-off Butterworth filters and the longer Savitzky--Golay and moving-average windows all achieve substantially higher $R_{\mathrm{noise}}$, but at the cost of a correlation below $0.90$: they remove too much of the terrain-relevant signal in the \SIrange{5}{20}{\hertz} band identified in \Cref{sec:bg-features-ml}. The effect of the selected filter on a representative segment of $a_y$, both in the time domain and in the power spectrum, is shown in \Cref{fig:filter_effect}.

\section{Segmentation and Windowing}
\label{sec:windowing}

The cleaning step removes contiguous blocks of samples (e.g.\ the robot slowing to a stop, or turning at the end of a row), so the filtered dataset is not strictly contiguous in time. A two-stage segmentation-then-windowing procedure (\texttt{05\_windowing.ipynb}) reconciles this with the fixed-size windows required by the feature extractor (\Cref{ch:feature}).

\subsection{Continuous-Segment Detection}

Within each run, consecutive samples are grouped into continuous segments by scanning the time differences $\Delta t_i = t_i - t_{i-1}$ and starting a new segment whenever
\begin{equation}
    \Delta t_i \;>\; \Delta t_{\mathrm{gap}}, \qquad
    \Delta t_{\mathrm{gap}} = \SI{25}{\milli\second} \;=\; 2.5\,\Delta t,
    \label{eq:gap_threshold}
\end{equation}
where $\Delta t = \SI{10}{\milli\second}$ is the resampled sample period (\Cref{sec:sync_resample}). The factor of $2.5$ tolerates an isolated dropped sample (which leaves $\Delta t_i = \SI{20}{\milli\second}$ between its neighbours) while reliably breaking on the multi-sample gaps left by the cleaning step. Each segment is recorded with its run identifier, start and end times, sample count, and label distribution.

\subsection{Fixed-Length Sliding Windows}

Each segment is then sliced into fixed-length, overlapping analysis windows:
\begin{align}
    W &= \SI{2.0}{\second} \;\;\equiv\;\; 200\,\text{samples},
        \label{eq:window_size} \\
    S &= W(1 - r) = \SI{1.0}{\second} \;\;\equiv\;\; 100\,\text{samples},
        \quad r = 0.5,
        \label{eq:step_size}
\end{align}
with $r$ the overlap ratio. The $\SI{2}{\second}$ window captures multiple cycles of the dominant terrain-driven oscillation ($\sim$\SIrange{5}{20}{\hertz}, tens of cycles per window) while leaving room for many windows per terrain segment. The $50\%$ overlap doubles the number of training examples and ensures that any transition crossing a window boundary appears in at least one window, which is useful for the transition analysis in \Cref{ch:results}. Windows never straddle a gap, so no window mixes pre and post-cleaning samples. This follows the standard recipe in the activity-recognition and terrain-classification literature~\cite{Brooks2005,Bao2004}.

\subsection{Window Label Assignment}

Each window inherits a single terrain label from the per-sample labels inside it (the labelling stage of \Cref{sec:labelling_pipeline} runs before windowing). The window label is the \emph{majority} label of its constituent samples; ties are broken lexicographically. Because cleaning has already removed turning and stationary samples and the conservative label ranges explicitly exclude transition regions, the majority is unambiguous ($>\!90\%$ of samples within a window agree) in essentially all windows of the production dataset.

\subsection{Output of the Pipeline}

The windowing notebook produces a window-metadata table with one row per window and columns \texttt{window\_id}, \texttt{run\_id}, \texttt{segment\_id}, \texttt{label}, \texttt{t\_start}, \texttt{t\_end} and \texttt{n\_samples}. Together with the filtered per-sample dataset, this table is the input to the feature extractor described in \Cref{ch:feature}. \Cref{tab:window_counts} summarises the resulting per-class window counts for the campus and farm datasets.
